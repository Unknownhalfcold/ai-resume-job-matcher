# 项目执行路线

## 第 1 阶段：PRD + 原型

目标：先把产品讲清楚。

你需要完成：

- 明确目标用户
- 明确输入和输出
- 画出工具界面草图
- 准备 1 份简历样例和 1 份岗位 JD 样例

阶段成果：

- `docs/PRD.md`
- 简单页面草图
- README 初稿

## 第 2 阶段：Python Demo

目标：用代码跑通最基础的匹配分析。

建议先做：

- 读取简历文本和 JD 文本
- 提取关键词
- 计算关键词匹配率
- 输出匹配分数和缺失关键词

这一步的重点不是做得完美，而是证明你理解“简历和岗位匹配”可以被拆成可计算的问题。

## 第 3 阶段：LLM 优化建议

目标：让 AI 根据分析结果生成更自然的建议。

LLM 是 Large Language Model 的缩写，意思是“大语言模型”。人话版：就是像 ChatGPT 这样能理解和生成文字的 AI。

这一阶段要注意：

- 不要把 API Key 放进公开代码
- 让 AI 输出固定格式，方便前端展示
- 保留关键词匹配结果，避免完全依赖 AI 主观判断

## 第 4 阶段：网页展示

目标：把项目做成 GitHub 主页可以展示的作品。

有两种方式：

### 方式 A：GitHub Profile README

适合展示项目介绍、截图、Demo 链接和技术亮点。

这是最简单的 GitHub 主页展示方式。

### 方式 B：GitHub Pages

适合放一个真正能打开的网页。

GitHub Pages 可以理解为“GitHub 免费帮你托管静态网页”。静态网页指的是只包含 HTML、CSS、JavaScript 的页面，没有自己的服务器。

重要提醒：如果网页要直接调用 AI API，就不能只靠 GitHub Pages，因为 API Key 会暴露。

## 第 5 阶段：整理成简历项目

目标：把这个项目写成简历上的项目经历。

可以突出：

- 从 0 到 1 设计 AI 工具
- 构建关键词匹配评分逻辑
- 使用 LLM 生成简历优化建议
- 将项目部署并展示在 GitHub

## 推荐执行顺序

1. 完成 PRD
2. 补充 5 个目标岗位 JD
3. 用 Python 做本地 Demo
4. 加入 AI 建议生成
5. 做网页界面
6. 写 GitHub README
7. 写简历项目描述
