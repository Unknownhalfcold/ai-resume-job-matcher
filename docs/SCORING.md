# 评分逻辑说明

## 概述

当前 MVP 使用关键词权重匹配算法。

评分目标不是替代招聘判断，而是帮助候选人快速了解简历是否覆盖了岗位 JD 中的显性要求。

## 关键词模型

系统中的每个关键词包含：

- `name`：展示名称，例如 `SQL` 或 `需求分析`
- `category`：能力分类，例如产品能力、数据能力、技术能力、协作能力
- `weight`：重要程度
- `aliases`：同义表达或相关表达

关键词配置维护在 `data/keywords.json`，Python MVP 和 Web MVP 共用这份配置。

示例：

```python
Keyword("SQL", "数据能力", 4, ("sql", "mysql", "postgresql"))
```

## 分数公式

```text
匹配度 = 已匹配关键词权重 / 岗位关键词总权重 * 100
```

其中：

- 岗位关键词总权重：JD 中识别出的关键词权重总和
- 已匹配关键词权重：这些岗位关键词中同时出现在简历里的权重总和

## 示例

如果岗位 JD 中识别出的关键词总权重为 `53`，简历覆盖的关键词权重为 `23`：

```text
匹配度 = 23 / 53 * 100 = 43
```

最终展示为：

```text
43/100
```

查看计算明细：

```powershell
py -X utf8 scripts/analyze_match.py --debug
```

## 权重设计

不同岗位要求的重要性不同。

对于 AI 产品或数据相关岗位，`需求分析`、`数据分析`、`Python`、`SQL` 等能力通常比通用工具关键词更关键，因此会有更高权重。

## 分数解释

- `80-100`：关键词覆盖较强
- `60-79`：匹配度中等，存在部分能力缺口
- `40-59`：具备部分相关性，但优化空间明显
- `0-39`：与目标岗位的显性要求匹配较弱

## 当前边界

当前分数只衡量关键词层面的匹配，尚不能完整评估：

- 经历深度
- 项目质量
- 业务影响
- 表达清晰度
- 经验真实性
- 关键词之外的上下文相关性

这些能力将在后续 LLM 建议层中继续增强。
