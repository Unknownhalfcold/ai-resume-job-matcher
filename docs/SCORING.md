# 评分逻辑说明

## 目标

系统面向不同专业和岗位，不把某一份固定关键词表当作完整职业标准。

基础词库负责快速识别常见显性要求，LLM 根据当前 JD 动态识别专业要求，后端使用固定公式计算最终分数。

最终分数不是录用概率，只用于解释简历与当前岗位材料之间的匹配程度。

## 九步评分

1. 计算关键词匹配分。
2. LLM 判断语义匹配分。
3. LLM 判断经历匹配分。
4. LLM 判断简历质量分。
5. 计算证书和奖项等加分项。
6. 加权计算基础分。
7. 扣除缺失核心技能惩罚。
8. 应用分数上限规则。
9. 输出最终分数和修改建议。

## 加权公式

```text
加权基础分 =
关键词匹配分 × 25%
+ 语义匹配分 × 30%
+ 经历匹配分 × 30%
+ 简历质量分 × 15%
```

```text
上限前分数 =
加权基础分
+ 证书/奖项加分
- 核心技能惩罚
```

```text
最终分数 = min(上限前分数, 分数上限)
```

## 四个基础分

- **关键词匹配分**：简历是否直接覆盖 JD 中的常见技能、工具、方法和专业术语。
- **语义匹配分**：即使措辞不同，简历能力是否与岗位要求等价。
- **经历匹配分**：实习、项目、科研和工作经历的职责、深度、成果是否接近岗位预期。
- **简历质量分**：结构是否清晰，证据是否具体，是否有量化结果，表达是否可信且容易被 HR 快速理解。

## 加分规则

- 只分析简历中明确出现的证书、奖项、论文和研究成果。
- 相关性优先于知名度。
- 无法核验或与岗位无关时不加分。
- 全部加分项最多增加 5 分。

## 核心技能惩罚

LLM 先把 JD 要求分为：

- `must_have`：硬性核心要求。
- `important`：重要要求。
- `nice_to_have`：加分项。

如果 `must_have` 的简历证据低于 40/100，或完全缺失，后端按该要求的 1-5 权重计算惩罚。总惩罚最多 25 分。

## 分数上限

- 缺少两项及以上核心要求：最高 59 分。
- 缺少一项核心要求：最高 69 分。
- 语义匹配低于 30：最高 49 分。
- 经历匹配低于 35：最高 64 分。

当多条规则同时命中时，使用最低上限。

## 跨专业词库

基础词库覆盖软件、人工智能、数据、金融财会、商业运营、工程技术、自然科学、生命健康、法律公共事务、教育人文、设计创意和组织管理等岗位族。

词库仍不是完整职业本体。未命中的新学科、新工具和细分技能由 LLM 从当前 JD 动态识别，因此不会因为岗位不属于 AI 行业就直接得到零分。

## 录用背景基准

只有后端存在匿名、聚合并带来源说明的数据时，系统才能展示目标公司已录用候选人的背景分布，例如：

- 教育和院校层次。
- 奖项或专业证书。
- 论文和研究方向。
- 常见实习经历。

没有可靠数据时，页面必须明确显示“仅依据 JD 分析”，不得让模型根据记忆编造某公司的真实录用画像。
