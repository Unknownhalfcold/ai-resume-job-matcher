# PRD: AI 简历与岗位匹配度分析工具

## 1. 产品一句话

帮助求职者快速判断自己的简历和目标岗位是否匹配，并给出可执行的简历优化建议。

## 2. 目标用户

- 正在找实习或全职工作的学生
- 想申请 AI 产品经理、数据分析、商业分析、运营等岗位的求职者
- 不确定简历是否贴合岗位要求的人

## 3. 用户痛点

用户常见问题：

- 看不懂岗位描述里真正重要的能力要求
- 不知道自己的简历和岗位差在哪里
- 不知道该怎样修改简历才能更贴合目标岗位
- 每次投递都手动改简历，效率很低

## 4. MVP 功能

MVP 是 Minimum Viable Product，意思是“最小可行产品”。人话版：先做一个最小但能跑通核心流程的版本。

第一版只做 5 件事：

1. 用户粘贴简历文本
2. 用户粘贴岗位 JD 文本
3. 程序提取岗位关键词
4. 程序计算简历和岗位的匹配度分数
5. 程序输出修改建议

第一版暂时不做：

- 登录注册
- 在线保存历史记录
- PDF 上传解析
- 多语言切换
- 复杂可视化图表

## 5. 输入

### 简历文本

用户直接复制粘贴自己的简历内容。

### 岗位 JD

JD 是 Job Description 的缩写，意思是“岗位描述”。里面通常包含岗位职责、任职要求、加分项等内容。

## 6. 输出

工具应该输出：

- 总体匹配度分数，例如 78/100
- 匹配亮点，例如“简历中体现了数据分析、用户研究、项目管理”
- 缺口分析，例如“岗位要求 A/B 测试，但简历中没有相关经历”
- 关键词建议，例如“建议补充 SQL、用户增长、竞品分析”
- 简历改写建议，例如把普通描述改成更结果导向的表达

## 7. 核心用户流程

1. 用户打开工具
2. 粘贴简历
3. 粘贴目标岗位 JD
4. 点击“开始分析”
5. 查看匹配度和建议
6. 根据建议修改简历

## 8. 评分逻辑第一版

第一版先不用复杂 AI，先用关键词匹配做基础评分。

示例逻辑：

- 从岗位 JD 中提取关键词
- 检查这些关键词是否出现在简历中
- 匹配越多，分数越高
- 对重要关键词给更高权重

权重可以理解为“重要程度”。比如岗位反复提到 SQL，那么 SQL 的权重就比只出现一次的词更高。

## 9. AI 增强版

后续接入大模型后，可以让 AI 做这些事：

- 判断简历经历是否真的支持岗位要求
- 给出更自然的简历修改建议
- 按 STAR 法则改写项目经历
- 输出适合放进 GitHub README 的项目总结

STAR 法则是写简历经历的一种结构：

- Situation：当时是什么背景
- Task：你负责什么任务
- Action：你做了什么
- Result：最后带来了什么结果

人话版：不要只写“我做过什么”，要写“我在什么场景下做了什么，并带来了什么结果”。

## 10. 成功标准

这个项目作为 GitHub 主页作品，应该能证明你具备：

- 产品思维：能定义用户问题和产品流程
- 基础技术理解：能用 Python 做文本分析
- AI 应用能力：知道如何把大模型用于实际任务
- 表达能力：能把项目讲成别人看得懂的作品
